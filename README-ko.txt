설렘모먼트 모바일 웹 · Pages CMS 연동판
====================================

이제 관리자는 사진과 글자를 바꾼 뒤 Pages CMS에서 Save / 저장만 누르면 됩니다.
파일을 내려받거나 GitHub에 직접 업로드하는 작업은 처음 설치할 때만 필요합니다.

중요: 현재는 연동용 파일을 준비한 상태입니다.
실제 GitHub 저장소 생성, 최초 업로드, GitHub Pages 활성화,
Pages CMS 계정 연결은 아직 하지 않았습니다.
새 계정이나 저장소 이름이 정해지지 않아도 이 파일들을 그대로 사용할 수 있습니다.


처음 설치하는 사람에게
-----------------------
1. GitHub에 사이트를 운영할 계정으로 로그인하고 새 저장소를 만드세요.
   대표 사이트는 '계정아이디.github.io', 별도 사이트는 'photo' 같은 이름을 씁니다.
   무료 계정에서는 Public으로 만들고 Add README를 켜세요.
   이미 사이트 저장소가 있다면 기존 저장소를 사용할 수 있습니다.

2. 배포 ZIP을 압축 해제한 뒤 아래 파일/폴더를 저장소의 맨 위에 올리세요.

   index.html             고객용 다운로드 페이지
   관리자.html            관리자 안내 및 Pages CMS 바로가기
   site.json              CMS가 수정하는 사진·문구·예약 주소
   .pages.yml             Pages CMS의 한국어 편집 항목 설정
   .nojekyll              GitHub Pages 정적 파일 게시 설정
   media/photobooth.svg    기본 이미지 (media 폴더 전체를 올리세요)

   ZIP 자체나 ZIP을 푼 바깥 폴더를 올리는 것이 아닙니다.
   위 파일들이 저장소 첫 화면에 바로 보이게 올려주세요.
   .pages.yml은 앞에 점이 있는 파일입니다. 빠뜨리지 마세요.
   README-ko.txt와 관리자-사용법.txt는 안내문이라 올리지 않아도 됩니다.
   이 앱의 C# 소스나 credentials.json 등은 웹사이트에 올리지 마세요.

3. 저장소의 Settings → Pages에서 아래와 같이 설정하고 Save를 누르세요.
   Source: Deploy from a branch
   Branch: main (실제 기본 브랜치가 다른 이름이면 그 브랜치)
   Folder: / (root)

4. GitHub Pages 배포가 끝난 뒤 고객 페이지가 열리는지 확인하세요.
   대표 사이트: https://계정아이디.github.io/
   별도 사이트: https://계정아이디.github.io/저장소이름/

5. https://app.pagescms.org/ 에 접속해 GitHub로 로그인하세요.
   안내에 따라 Pages CMS GitHub App을 설치/연결하고,
   이 사이트를 올린 저장소를 사용할 수 있도록 선택하세요.
   계정/저장소 연결은 소유자 또는 권한이 있는 사람이 진행해야 합니다.
   화면이 달라 보이면 Pages CMS 공식 시작 안내를 참고하세요.
   https://pagescms.org/docs/quick-start/

6. Pages CMS에서 해당 저장소와 GitHub Pages가 게시하는 브랜치를 선택하세요.
   첫 화면에 '다운로드 페이지 꾸미기' 항목이 보이면 설정을 읽은 것입니다.
   새 설정 파일을 만들라는 안내가 나오면 .pages.yml이 저장소 맨 위에 있는지,
   올바른 저장소와 브랜치를 선택했는지 확인하세요.

7. '다운로드 페이지 꾸미기'를 열고 실제 사진·스마트스토어 주소를 넣어 저장하세요.
   기본 예약 주소는 비어 있습니다. 입력 전에는 고객 예약 버튼이 작동하지 않습니다.
   저장 후 GitHub의 Actions/Pages에서 배포가 완료됐는지 확인하세요.

8. 관리자는 고객 주소 뒤에 '/관리자.html'을 붙여 접속하면 됩니다.
   예: https://계정아이디.github.io/관리자.html
   예: https://계정아이디.github.io/photo/관리자.html
   이 주소를 관리자의 즐겨찾기에 넣어주세요.
   관리자에게는 '관리자-사용법.txt'만 전달하면 됩니다.


이전에 만든 단일 HTML 버전에서 바꿀 때
---------------------------------------
- 이제 index.html 한 파일만으로 설정을 변경하는 방식이 아닙니다.
  반드시 site.json, .pages.yml, .nojekyll, media 폴더를 함께 올리세요.
- 기존에 바꿔둔 이미지·문구·예약 주소가 있으면 새 Pages CMS에 같은 내용을 넣으세요.
  새 파일을 덮어쓰기 전에 현재 운영 파일을 복사해 보관해 두면 좋습니다.
- 관리자의 수정 내용은 site.json과 media 폴더에 저장됩니다.
  이후 프로그램 업데이트를 올릴 때는 운영 site.json과 media를 무심코 덮어쓰지 마세요.
- 이전 버전 관리자.html도 이번 파일로 교체하세요. 파일 저장 편집 기능은 대체됐습니다.


관리자가 바꿀 수 있는 항목
---------------------------
가운데 사진, 맨 위 제목, 제목 아래 문구, 사진 설명,
분홍색 안내 상자 문구, 파란색 버튼 글자, 초록색 버튼 글자,
스마트스토어 예약 주소를 바꿀 수 있습니다.

사진은 Pages CMS의 이미지 항목에서 선택하거나 업로드합니다.
JPG/PNG/WEBP 등 세로 사진을 권장합니다. 기존 기본 일러스트는 SVG입니다.
안내 문구를 지우면 안내 상자가 사라집니다.
예약 주소는 https://로 시작하는 주소를 쓰세요.
관리자 화면의 미리보기 버튼은 실제 다운로드나 예약 페이지로 이동하지 않습니다.
실제 동작은 고객 페이지 또는 인쇄된 QR로 확인하세요.


저장과 게시에 관해
------------------
- Pages CMS에서 Save를 누르면 설정이 GitHub 저장소에 저장됩니다.
- GitHub Pages가 그 저장 내용을 게시한 뒤 고객 페이지가 바뀝니다.
- 항상 즉시 바뀌는 것은 아닙니다. 잠시 기다린 뒤 관리자 화면의
  '게시한 내용 다시 확인'을 누르세요.
- 다른 브랜치에 저장하면 고객 페이지에는 반영되지 않습니다.
  초기 연결 때 Pages가 게시하는 브랜치와 CMS 편집 브랜치를 맞춰주세요.
- 공개 관리자.html은 편집 도구를 여는 안내 페이지입니다.
  실제 수정·저장은 Pages CMS에서 로그인하고 저장소 권한을 확인한 뒤 이뤄집니다.
- GitHub 비밀번호나 접근 토큰을 site.json이나 웹페이지에 넣지 않습니다.


기존 QR과 새 주소
-----------------
- p=파일ID, photoId=파일ID, 기존 photoUrl=사진주소를 계속 지원합니다.
- 영상 다운로드 버튼은 제거됐으며 videoUrl은 더 이상 사용하지 않습니다.
- 사진 QR 없이 접속하면 사진 다운로드 버튼은 작동하지 않습니다.
- 설정 파일을 읽지 못해도 유효한 QR의 사진 링크는 동작합니다.
- Google Drive 업로드/공유 완료 전에는 다운로드가 아직 불가능할 수 있습니다.
- 웹페이지는 업로드 상태나 저장 완료 여부를 확인하지 않습니다.
- GitHub 계정을 바꿔 새 주소를 쓰면 앱의 MobileDownloadPageUrl도 바꿔야 합니다.
  기존에 인쇄한 QR을 쓰려면 예전 주소의 웹페이지를 계속 유지하세요.
- MobileDownloadUseFileId=true는 새 페이지를 먼저 게시하고 실제 p=파일ID
  다운로드를 확인한 다음 적용하세요. 이 작업에서는 앱 설정을 바꾸지 않았습니다.


개발 확인용 (관리자는 읽지 않아도 됩니다)
-----------------------------------------
node MobileWeb/tests/mobile-web.test.cjs
Windows에 설치된 Chrome/Edge로 로컬 테스트 서버를 열어 검증합니다.
실제 GitHub 로그인·CMS 저장·원격 배포·Drive 다운로드는 수행하지 않습니다.
.pages.yml은 JSON 표기법으로 작성된 유효한 YAML입니다.
